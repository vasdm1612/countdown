# Tile & Timer v7 / «Буквы и числа»

Независимая браузерная игра на русском и английском языках по мотивам словесно-числовых телевизионных викторин. Одиночная практика и онлайн-комнаты до 6 игроков. `index.html` содержит интерфейс, `server.js` — встроенный HTTP-сервер и доверенный серверный таймер. Для прямого соединения браузеров по-прежнему используется PeerJS/WebRTC.

## Изменения версии 7: случайные и усложнённые числовые задания

Теперь в настройках матча появился отдельный переключатель **«Генерация целевого числа»**. Значение по умолчанию — **«Случайная цель (101–999)»**. Число равномерно выбирается в диапазоне 101–999 независимо от выпавших числовых фишек. Как и в классическом Countdown, точное попадание **не гарантируется**: можно искать максимально близкое значение, получая баллы по правилу `max(0, 10 − |результат − цель|)`. В этом режиме программа **не использует степени и корни для генерации числа**, но достижимость только четырьмя базовыми операциями не обещается.

Второй режим — **«Точно решаемая цель (+ − × ÷)»** — сохраняет гарантию существования точного выражения из выпавших фишек без степеней и корней. Генератор проверяет, какие результаты получаются за одну–две операции, и по возможности исключает их; рассматривает 2400 случайных комбинаций и выбирает **равновероятно среди разных найденных результатов**, а не из первых 12, как в прежней версии. Для неудачных или вырожденных наборов (например, четырёх единиц) может появиться число меньше 101, поскольку гарантировать трёхзначную достижимую цель математически невозможно. При создании комнаты эту настройку выбирает ведущий до начала матча, гости получают её вместе с остальными параметрами игры. Логика генерации одинакова для русского и английского режимов.

И в одном, и в другом режиме игрок может применять `^` и `√` по обычным правилам допустимости промежуточных положительных целых значений; они не используются самим генератором. Серверный таймер версии 6, независимое начисление очков за близкие ответы, необязательный таймер голосования и ручной/автоматический ведущий сохранены.

## Изменения версии 6: серверное начало отсчёта

**Как теперь запускается время.** При размещении игры как Node.js Web Service на Render создаётся небольшой собственный сервер. При нажатии **«Запустить таймер»** (либо при автоматическом запуске раунда) браузер ведущего посылает запрос `POST /api/round/start`. Сервер фиксирует свой момент обработки команды — `startedAt` — и вычисляет `endsAt = startedAt + длительность`. **Только после подтверждения сервером** браузер ведущего показывает запущенный раунд и рассылает участникам эти абсолютные метки. Получение сообщения с задержкой НЕ запускает для гостя новый полный таймер: отображается фактический остаток. Браузеры периодически сверяют часы с `/api/time` с учётом сетевой задержки (несколько запросов и выбор самого быстрого). При недоступности сервера начало раунда не подтверждается, и таймер не запускается; можно повторить попытку.

Нажатие **«Начать игру»** в ручном режиме всё ещё переводит в стадию **выбора фишек**, а отсчёт начинается по отдельной кнопке **«Запустить таймер»**. В автоматическом режиме ведущий выбирает фишки и отправляет серверу команду начать отсчёт самостоятельно. В одиночной игре таймер локальный.

Если разместить только `index.html` на **Static Site**, серверных маршрутов `/api/time` и `/api/round/start` нет: игра продолжит работать по старым правилам, а авторитетными будут часы браузера ведущего. Гостевые браузеры синхронизируют оценку его времени через Ping/Pong. Это **не настоящая серверная фиксация** времени; интерфейс показывает «Таймер от времени ведущего». Для требуемого серверного поведения нужен описанный ниже **Web Service**.

**Важно:** новый сервер отвечает за время начала и HTTP-раздачу сайта, но игровое состояние, ответы, голосование и локальные рейтинги пока по-прежнему обрабатываются в браузере ведущего через PeerJS. Это **не** полностью защищённый централизованный игровой сервер и не серверная база профилей. Сервер хранит временные сведения о комнатах в памяти; при рестарте Render они сбрасываются и активную комнату нужно создать заново. Даже при синхронизации часы в разных браузерах могут слегка отличаться из-за сетевой задержки; последнее слово о принятии ответа в текущей архитектуре остаётся за браузером ведущего.

### Публикация в Render.com с серверным таймером

1. Загрузите **содержимое** архива на GitHub в корень репозитория: `index.html`, `server.js`, `package.json`, `render.yaml`, `README.md`.
2. Зайдите в https://dashboard.render.com/ и нажмите **New → Web Service** (именно *Web Service*, а **не** *Static Site*).
3. Подключите репозиторий GitHub. Выберите среду **Node** и подходящий тариф (если бесплатный доступен в аккаунте, его достаточно для небольших дружеских партий).
4. Параметры: **Build Command** — `npm install --omit=dev`; **Start Command** — `npm start`. Root directory оставьте пустым. `render.yaml` также можно использовать как Blueprint, если Render предлагает импорт конфигурации.
5. После деплоя откройте `https://ИМЯ-САЙТА.onrender.com/api/health` — должны появиться поля `ok: true` и `clock: "server"`. Затем откройте главную страницу игры.
6. Создайте онлайн-комнату. В боковой панели должно отображаться **«Таймер от времени сервера»**. Если вместо этого указано **«Таймер от времени ведущего»**, серверный режим не включился: проверьте, что создан именно Web Service, а `/api/health` открывается.

Для локального теста при установленном Node.js 20+: `npm start`, после чего открыть `http://localhost:3000`. Установка дополнительных npm-библиотек не требуется. Для проверки обработчика времени используйте `npm test`.

## Изменения версии 5: начисление очков и голосование без таймера

**Числовые раунды.** Теперь каждый участник с допустимым арифметическим выражением получает баллы **независимо от результата остальных** по формуле `max(0, 10 − |полученное число − цель|)`. Например, при цели 500 ответ 500 даёт 10 очков; 499 или 501 — 9; 495 или 505 — 5; 490 или 510 — 0. За разницу больше десяти также 0, отрицательных очков нет. Если выражение недопустимо или ответ отсутствует, начисляется 0. Эта формула используется также в суммарном счёте и итоговом рейтинге в рейтинговом матче.

**Таймер голосования.** В настройках одиночной игры и онлайн-комнаты есть опция **«Ограничить голосование 15 секундами»** (по умолчанию включена). Если её отключить, за голоса можно голосовать сколько угодно:

- **Ручной ведущий:** голосование продолжается до нажатия кнопки «Следующий раунд». Ведущий не видит чужих ответов заранее; они открываются всем после окончания игрового таймера. Нажимая переход, ведущий закрывает голосование и фиксирует поданные голоса.
- **Автоматический ведущий:** буквенный раунд с голосованием остановится на результатах. Создатель комнаты нажимает **«Завершить голосование»**, после чего следующий раунд начинается автоматически спустя 5 секунд. Это необходимо, чтобы игра не закрывала голосование сама при отключённом таймере.
- Если нет других игроков, которым можно голосовать, ожидания нет: автоматический режим продолжает работу.

Без таймера правила голосования остаются прежними: нельзя голосовать за своё слово, отклонение при большинстве голосов «против», при равенстве слово засчитывается. В онлайн-комнате настройку выбирает создатель до игры; она синхронизируется у остальных.

## Быстрый запуск

**Одиночная игра.** Распакуйте архив, дважды щёлкните `index.html`, выберите RU/EN, настройки и «Одиночная игра». Установка Python и подключение к интернету не требуются (если не считаете загрузку сетевой библиотеки, которая в одиночном режиме не нужна).

**Играть с друзьями.** Для серверного таймера опубликуйте игру на Render как **Node Web Service** (инструкция выше). На обычном HTTPS-статическом хостинге серверный таймер недоступен, используется время ведущего. Откройте сайт, выберите «Создать онлайн-комнату», задайте имя и настройки, отправьте код или ссылку друзьям. Ведущий должен держать страницу открытой. Для сетевой работы нужен интернет, внешний PeerJS-сервис и доступность прямых WebRTC-соединений между браузерами. Подключения могут блокироваться некоторыми сетями. Проверка соединения нескольких удалённых устройств в этой версии не проводилась.

**Английский режим.** Переключатель RU/EN вверху меняет язык интерфейса; «Язык слов» в настройках меняет язык букв и анаграмм для всей комнаты независимо от интерфейса.

## Изменения версии 4: ручной ведущий и равные условия

**Автоматический ведущий необязателен (по умолчанию выключен).** Перед матчем снимите/оставьте снятой галочку «Автоматический ведущий». Тогда создатель комнаты запускает матч кнопкой, выбирает типы букв вручную или нажимает «Случайный набор», в числовом раунде выбирает количество больших чисел и нажимает «Раздать числа», затем запускает общий таймер. После окончания раунда, проверки ответов и голосования на его экране появляется **«Следующий раунд»**. Последний раунд завершается кнопкой «Итоговая таблица». Переход до истечения времени на голосование недоступен. Финальная анаграмма запускается автоматически после перехода к ней, но **не заканчивается досрочно** после первого правильного ответа: чтобы все участники могли ответить, время для неё идёт до конца. При включённой автоматике программа по-прежнему самостоятельно выбирает фишки и переводит игру дальше.

**Равные условия получения информации.** На стадии «Идёт время» на серверную часть комнаты в браузере ведущего (при работе по сети) отправляется только криптографический SHA-256-отпечаток ответа каждого участника с индивидуальной случайной солью; текст ответа до конца времени не передаётся. По истечении таймера начинается короткая стадия «Проверка ответов». Браузеры присылают тексты и соли, ведущий проверяет соответствие отпечаткам и затем **одновременно открывает ответы всем** в фазе «Результаты». Ведущий не получает специального права заранее показывать ответы, отключена кнопка досрочного завершения раунда. Ручное отклонение слова ведущим сохранено только в одиночном режиме: в сетевом матче слова решаются голосованием. Количество присланных ответов (без текста) видно каждому.

Финальная девятибуквенная анаграмма формируется из общего для обоих языков списка слов; её правильный ответ **не сохраняется в состоянии ведущего** до открытия результатов. Решение числовой задачи теперь может запросить **любой** игрок, но только после завершения времени. Раннее раскрытие чужих ответов через обычный интерфейс и сообщения сети не предусмотрено.

**Ограничения честности:** хостом всё ещё служит браузер игрока, а не доверенный сервер; человек, намеренно меняющий JavaScript игры, может вмешаться в правила и результаты. Списки финальных слов открыты в файле игры и доступны любому игроку, поэтому для защищённой соревновательной игры необходим внешний сервер с секретными заданиями. Между моментом окончания таймера и публикацией результатов предусмотрено до 5,5 секунд на обмен подтверждениями: если игрок отключился в этот период, его нераскрытый ответ может не засчитаться. Для сетевой криптографии нужен HTTPS-хостинг (например, Netlify); автономная игра в современных браузерах поддерживает локальное открытие файла при доступности WebCrypto.

## Возможности версии 3 (сохранены в версии 7)

### 1. Расширенные числовые операции

Разрешены `+`, `−`, `×`, `÷`, скобки, **возведение в степень `^`** и **квадратный корень `√`**. Например, `2^3` = 8, `√(25)` = 5, `√(9+7)` = 4. Каждое исходное число можно использовать максимум столько раз, сколько его фишек на поле; промежуточные результаты должны быть положительными целыми числами и не превышать 99999. Корень должен быть точным целым, дроби не принимаются. Правила одинаковы в ручном вводе и калькуляторе из фишек.

**Важно (обновлено в версии 7):** теперь *по умолчанию* используется независимое случайное целевое число 101–999; оно может оказаться недостижимым точно с помощью обычной арифметики. Если требуется гарантировать точное решение без `^` и `√`, в настройках выберите **«Точно решаемая цель (+ − × ÷)»**. В этом режиме для чрезвычайно слабых наборов чисел цель иногда меньше 101. Кнопка «Показать пример решения» после раунда ищет выражение на обычных арифметических операциях и показывает найденный вариант (поиск ограничен по времени/числу перебираемых состояний, поэтому не всегда доказывает, что ближайшего решения не существует).

### 2. Калькулятор с промежуточными результатами

В настройках перед матчем включите **«Показывать промежуточные вычисления»**. Во время числовых раундов калькулятор отображает результат составленного выражения и пошаговые арифметические операции. Калькулятор поддерживает обычный ввод с клавиатуры, набор из предложенных чисел и операций, удаление, перестановку блоков, перетаскивание мышью.

### 3. Переменное количество фишек

В настройках задаётся **5–12 букв** или **4–8 чисел** для обычных раундов. Количество гласных зависит от выбранной длины: минимум `floor(N/3)`, максимум `ceil(N/2)`. Буквы выбираются из частотных русских/английских мешков без возвращения в пределах раунда. Больших чисел можно выбирать 0–4. Финальная анаграмма всегда состоит из девяти букв.

За лучшее принятое слово длиной менее девяти букв дают по одному очку за букву, за слова длиной **9 и более букв** — по два очка за букву. Длинные слова в данной реализации проверяются только на возможность составить их из букв; полноценного словаря по-прежнему нет.

### 4. Бонусная буква ×2

Включите **«Бонусная буква (раунды 2–3)»**. Во втором и третьем раундах игры, **если этот раунд буквенный**, с вероятностью 50% выбирается случайная буква из выпавших фишек. Буква показывается на экране. Игрок, составивший лучшее принятое слово с этой буквой, получает **вдвое больше очков**. При равной длине слов каждый из победителей раунда получает причитающиеся очки; удвоение применяется индивидуально при наличии бонусной буквы. В числовых и финальных раундах бонус не разыгрывается.

### 5. Финальная анаграмма без множественного числа

Наборы русских и английских финальных слов отобраны вручную: исключены **существительные во множественном числе** (русские словоформы типа «участники», английские типа `elephants`). Используется ограниченный встроенный список; это не полный лексический словарь. Запрет на множественное число относится к **финальной анаграмме**, а не к любому слову в обычном буквенном раунде.

### 6. Автоматический ведущий и голосование

Если включён «Автоматический ведущий», после нажатия начала матча программа автоматически выбирает буквы/числа, запускает таймер и переводит игру к следующему раунду. После стадии подтверждения ответов в обычном буквенном раунде голосование по умолчанию открыто на **15 секунд**, после чего ещё 5 секунд отображается результат. Опционально таймер голосования можно отключить; тогда оно продолжается до решения ведущего (см. раздел об изменениях версии 5). В числовом и финальном раундах следующий раунд начинается через 7,5 секунд после завершения предыдущего.

Игроки нажимают **«Засчитать»** или **«Отклонить»** под словом другого игрока. Сам за своё слово голосовать нельзя. Слово отклоняется, если голосов «против» больше, чем «за»; ничья и отсутствие голосов означают зачёт. Очки пересчитываются по решениям голосования. Без автоматического ведущего переходы остаются под управлением ведущего, но он больше не может единолично отменять слова в сетевой игре. Автоматической проверки существования слова в реальном словаре нет: игроки проверяют слова через приложенную ссылку на Викисловарь.

### 7. Профили, статистика и рейтинг

На стартовом экране есть профили: создать, переключиться, просмотреть накопленные результаты и локальную таблицу рейтинга. Хранится рейтинг (начальная величина **1000**), количество рейтинговых матчей, побед, набранных очков, точных числовых решений и максимальная длина слова. Впервые подключающийся игрок может создать локальный профиль.

При создании комнаты включите **«Рейтинговый матч»**. Рейтинг и статистика обновляются **только** после завершения такого онлайн-матча, если участвовали минимум два игрока. Обычная игра без галочки, одиночная практика и досрочно покинутые матчи не записываются в рейтинг. Рейтинг изменяется по парным сравнениям результатов по принципу Elo (K=24). При ничьей оба игрока получают 0,5 за сравнение; в матче больше двух игроков учитываются все пары. Один матч записывается в профиль не более одного раза.

**Ограничение:** серверный модуль обеспечивает только таймер, но не хранит аккаунты и рейтинг. Единой серверной системы авторизации и регистрации пока нет. Профиль, статистика и история матчей хранятся в **localStorage этого браузера**, а не в глобальной базе пользователей. Во время онлайн-матча игрок отправляет свой текущий рейтинг ведущему, тот вычисляет изменение рейтинга для каждого участника, и каждый браузер записывает результат локально. Это подходит для дружеских игр, но не защищает от подмены рейтинга, очистки браузера, повторных подключений с новым профилем и других манипуляций. Для единого рейтинга с авторизацией и синхронизацией между устройствами необходимы сервер, база данных и вход в аккаунт.

Для переноса статистики воспользуйтесь **«Экспорт профиля»** (JSON) на старом устройстве и **«Импорт профиля»** на новом. Импорт создаёт отдельный локальный профиль; изменения между устройствами автоматически не синхронизируются. Никогда не импортируйте файлы от незнакомых людей.

## Примечания

- В начале матча задаются язык слов, длительность таймера 10–300 секунд, 5 или 7 раундов, количество фишек, автоматический ведущий, калькулятор, бонус и рейтинговость.
- Игроки с уже созданными аккаунтами веб-сайтов **не могут** использовать их для входа в эту игру. Профили локальные.
- В текущем расписании формата «Быстрая игра» раунд №2 — числовой, №3 — буквенный. Следовательно, бонус может выпасть только в раунде №3. В формате «Студийная игра» раунды №2 и №3 буквенный и числовой соответственно; бонус — только в раунде №2. Изменение формата или расписания может поменять расположение бонусных раундов.
- Сервер Render задаёт временные метки начала/окончания раунда (только при размещении Node Web Service). Ведущий комнаты остаётся источником остального игрового состояния в сетевой игре. Не закрывайте его вкладку.

## English short guide

Extract ZIP and open `index.html` for solo play, or upload the folder to HTTPS static hosting for online rooms. The host keeps their tab open. Automatic hosting is optional and OFF by default: in manual mode, the host starts the timer and advances with a **Next round** button after the result and voting windows. Players send salted SHA-256 answer commitments before the deadline; plaintext is transmitted only after time expires, verified, and revealed to everyone in one result state. The host cannot finish the timer early. The host does not store a hidden conundrum solution. The number solver is available to all after the round. This protects ordinary rooms, not against an intentionally modified client; reliable ranked competitions require a trusted server. Configure **5–12 letter tiles**, **4–8 number tiles**, the round timer, **automatic host**, **step-by-step calculator**, **random bonus letter in rounds 2–3**, and whether the match is **rated**. Powers (`^`) and exact integer square roots (`√`) are allowed. By default the target is independently random (101–999), so an exact solution is not guaranteed; switch to Guaranteed solution to ensure a target reachable via + − × ÷ alone. The final anagram pool excludes plural nouns. Online peers may vote accept/reject on each other's words for 15 seconds by default; the voting clock can be disabled, in which case the host ends voting using Next round (manual mode) or Close voting (automatic mode); ties count as accepted. Player profiles, ratings and statistics are **stored in the current browser only**, not on a central server. Each player receives independent numbers-round points using max(0, 10 − absolute difference from target). You can export/import JSON profiles manually. Unrated games do not change statistics.

## English: server-clock setup (v6)

To start every round at the time the **server processes** the host's Start request, deploy this project as a **Node Web Service** on Render (not a Static Site). Push `index.html`, `server.js`, `package.json`, `render.yaml` and `README.md` to GitHub. Render: New → Web Service → connect repository → runtime Node, build `npm install --omit=dev`, start `npm start`. Check `/api/health` for `clock: "server"`; rooms show **Server-authoritative round clock**. The host's Start action triggers `POST /api/round/start` and the countdown is anchored to its returned `startedAt` and `endsAt`. Guests estimate server time via `/api/time`; network delay does not grant a fresh full timer. In manual host mode, **Start game** enters tile selection and the later **Start clock** button sends the server request. On static hosting, the legacy host-clock fallback is clearly marked. PeerJS/WebRTC still carries gameplay state; the server does **not** store global player profiles or guarantee anti-cheat game-state enforcement.

## English: v7 number target generation

**Random target (default):** a uniformly selected integer 101–999, independent of the dealt tiles. Exact solutions are not always possible. The numbers round still awards each player `max(0, 10 − difference)` points for a valid expression. **Guaranteed solution:** randomly samples many valid calculations using only +, −, ×, ÷, avoids targets solvable in one or two operations where possible, and chooses from the distinct candidate values. Extremely restrictive tile selections may require targets below 101. Both settings work on solo and online games, including Russian/English word modes.
